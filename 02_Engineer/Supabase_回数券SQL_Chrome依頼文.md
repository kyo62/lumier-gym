# Supabase に「回数券」の SQL（003）を実行する：Claude in Chrome への依頼文

作成：2026-11-25　／　状態：未実施（代表がパソコンで実行する）

## 何をするのか
会員ページのカルテを回数券に作り直したので、Supabase のデータベースにも「回数券テーブル」を足す。
**これを実行するまで、本番の会員ページのカルテ（施術者の画面・お客様の画面）は動かない。**（デモモードは影響なし）

## 前提・注意
- 対象は、すでに作ってある Supabase プロジェクト `toneka-member`。
- 実行する SQL は `web/supabase/migrations/003_tickets.sql`。**1回だけ**実行する（2回目はエラーになる＝二重に実行されない）。
- この SQL は、`clients` テーブルの古い列（プラン・残り・繰越・ストレッチ回数券）を**削除**する。
  - すでにカルテを入れていた場合、残り回数は「その他の券」として**自動で引き継ぐ**（残りがあるものだけ）。
  - そのため、**Supabase が「破壊的な操作です」という確認を出すことがある。これは想定どおり**。ただし、押すのは代表自身が行う（下記）。
- ログイン・認証・確認ボタンの最終クリックは、代表が行う。service_role キー・データベースのパスワードには触れない。

