## B. サイトを置く（Cloudflare Pages・無料・商用可）

**先に決めること（代表）：** サイトを外部に置くのは「外部に出る判断」です。
`*.pages.dev` のURLは**秘密ではなく、知っていれば誰でも開けます**。LPには仮の文言（`example.com` など）が残っています。
→ 公開前は `NEXT_PUBLIC_NOINDEX=1` を設定して**検索結果に出さない**ようにします（実装済み）。URLは他の人に教えないでください。

1. **作業を `main` に取り込む。** いまの作業は `claude/posture-salon-launch-rxlgl5` ブランチにあり、`main` には入っていません。
   → **Claude に「PRを作って」と伝えてください**（作成は依頼があったときだけ行います）。マージは代表が行います
2. **Cloudflare のアカウントを作る** → https://dash.cloudflare.com/
3. **Workers & Pages → Create → Pages → Connect to Git** で、GitHub の `kyo62/lumier-gym` を選ぶ（画面の名称は変わることがあります）
4. **ビルドの設定**

   | 項目 | 値 |
   |---|---|
   | Production branch | `main` |
   | Root directory | `web` |
   | Build command | `npm run build` |
   | Build output directory | `out` |
   | 環境変数 | `NEXT_PUBLIC_NOINDEX` = `1` |

   - Node のバージョンは `web/.node-version`（22）で固定済みです
   - **環境変数は、Production と Preview で別々に設定されます。** `main` 以外のブランチで試すなら、Preview にも同じ値を入れてください
5. **Save and Deploy** → 完了すると `https://（プロジェクト名）.pages.dev` ができる
6. **スマホで確認する：** `https://（プロジェクト名）.pages.dev/member` を開く
   - ログインコードは `123456`（デモモード）
   - **iPhone（Safari）：** 共有ボタン → 「ホーム画面に追加」／**Android（Chrome）：** メニュー → 「ホーム画面に追加」
   - ここで初めて、**実機での「ホーム画面に追加」と、入力した記録が残ること**を確認できます

参考：
- [Cloudflare Pages：静的な Next.js サイトのデプロイ](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/)
- [Cloudflare Pages：ビルドの設定](https://developers.cloudflare.com/pages/configuration/build-configuration/)

## C. 本番のデータ保存にする（Supabase）

**⚠️ この段階が終わるまで、会員にURLを教えないでください。**
（手順の詳細は [`../web/README.md`](../web/README.md) の「会員ページ」。ここは順番と注意点です）

1. **Supabase のアカウントとプロジェクトを作る** → https://supabase.com/dashboard
   - **リージョンは「Northeast Asia (Tokyo)」**
2. **SQL Editor** に [`../web/supabase/migrations/001_member_area.sql`](../web/supabase/migrations/001_member_area.sql) を貼って実行（1回だけ）
3. **Authentication の設定**
   - **新規登録（Allow new users to sign up）をオフ** ← 必ず
   - **メールのテンプレート（Magic link）に `{{ .Token }}` を入れる**（README に貼り付ける文面あり）
   - 参考：[Passwordless email sign-in](https://supabase.com/docs/guides/auth/auth-email-passwordless)、[Email Templates](https://supabase.com/docs/guides/auth/auth-email-templates)
   - コードの仕様：**同じ人が再送できるのは60秒に1回、有効期限は1時間**（既定値。上のドキュメントより）
4. **メール送信（SMTP）を設定する ← 必須**
   - Supabase 標準のメール送信は**1時間に2通程度**しか送れません（[参考](https://zenn.dev/daimyo404/articles/3fefe4ef2d9500)）。これでは実質的にログインコードが届きません
   - カスタムSMTPを設定すると、上限が上がります（設定時の既定は30通/時間。[参考](https://zenn.dev/miyamoto610/articles/faf212aafd0997)）
   - **選択肢**

     | 案 | 内容 | メリット | デメリット |
     |---|---|---|---|
     | **A（推奨）** | **ドメインを取得して Resend を使う**（https://resend.com） | 送信元が `@自分のドメイン` で信頼されやすい。Supabase と連携できる | ドメインが先に必要（費用・商標確認が前提） |
     | B | 当面は Gmail の SMTP（アプリパスワード）を使う | ドメイン不要ですぐ始められる | 送信元が個人のGmailになる。到達率・Googleの制限は**未確認** |
     | C | 会員ログインは、ドメインが決まるまで待つ | 手戻りがない | 会員ページを使い始められない |

   - **これは「お金が出る」「後から変えにくい」判断なので、代表が決めてください**
5. **自分（施術者）を管理者にする**
   - Authentication → Users → **Add user → Create new user**（自分のメール。**Auto Confirm User** にチェック）
   - SQL Editor で `update public.profiles set is_admin = true where id = (select id from auth.users where email = '自分のメール');`
6. **サイトに接続情報を渡す**
   - Supabase の **Project Settings → API** から Project URL と **anon（公開）キー**
   - Cloudflare Pages → Settings → Environment variables に、**Production と Preview の両方**へ
     `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **`service_role` キーは絶対に入れない**
   - **値は「ビルド時」に埋め込まれるので、設定したあとに再デプロイ**（Deployments → Retry deployment）
7. **動作確認（本番のURLで、実際に）** ← 必須。ブラウザ→Supabase の通信部分は、ここで初めて確かめられます
   - 自分のメールでログイン → 施術者メニューが出る
   - 別のメールの会員を1人作り、ログインして記録を入れる → 施術者メニューの「会員の記録」に出る
   - **その会員から、ほかの会員の記録が見えないこと**
   - 会員を追加するときは、手順5の「Create new user」で登録します
