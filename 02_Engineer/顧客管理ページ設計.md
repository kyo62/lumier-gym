# 顧客管理ページ設計

作成：2026-10-16　／　状態：**初版を作成（デモデータで動作確認済み）。実際のお客様の情報はまだ入れない**

## 結論：HPとは「別々」にする（いまは）

### 事実
- HP（`toneka.jp`）は、誰でも見られる静的サイト（Next.js）。
- 会員ページ（`web/src/app/member/**`）は、Supabase につなぐ設計がすでにある（[`顧客向けアプリ構想.md`](./顧客向けアプリ構想.md)）。
- このリポジトリは**公開**。顧客情報は入れられない。

### 意見・推奨（AIの判断）
1. **いま**：HPに紐づけず、単体ファイル（`web/tools/顧客管理/index.html`）として別に持つ。HPからリンクしない・検索に出さない。
   - 理由：顧客情報（要配慮個人情報を含む）が、公開サイトと同じ場所にあるのは危険。開業前なので、まず使い勝手を確かめたい。
2. **将来**：同じ Supabase と同じ顧客IDで、会員ページの管理画面（`/member/admin`）に**統合**する。
   - 理由：お客様が見る会員ページと、施術者が見るカルテを、同じデータにできる。端末をまたいで使える。
3. それまでは、実在のお客様のデータを入れる前に、バックアップの運用（週1回・暗号化）を決める。

## 制約・注意
- データは**ブラウザの中だけ**。端末を替える・ブラウザのデータを消すと消える → バックアップ必須。
- 暗証番号は、画面の切り替え用の簡易的なもの。**暗号化ではない**。端末自体にロックをかける。
- 同意（個人情報の取扱い）のチェックがないと、問診票は送れない。
- アーティファクト版（claude.ai）ではファイル保存ができない。バックアップは「コピー」を使う。
